# 工程方案生成

从已确认事实形成明确的主推荐方案，同时生成可测量的工程量清单骨架。只有存在真实技术取舍时，提供一至两个条件备选。需要类别做法时读取 [references/category-scheme.md](references/category-scheme.md)。

## 工作流

1. 明确问题、位置、对象、包含范围和排除范围。若输入包含“本版本确认工程范围”，它是本版本方案与工程量的唯一边界；不得扩大回原申报范围，也不得遗漏该范围中的对象。
2. 选择与病害机理、设备接口和实施条件匹配的技术路径。
3. 形成目标、范围、工艺、材料原则、风险措施和验收方式六个模块。
4. 从方案步骤反推需要现场测量的对象、规格、单位和计量依据。
5. 检查方案与停机、消防、动火、隐蔽、高处、占用区和第三方检测条件是否闭环。
6. 判断是否存在永久治理与临时处置、局部修复与整体翻修、不同停机窗口等实质取舍；不存在时不要强行生成备选。
7. 备选方案必须说明适用条件，并独立生成完整六模块和工程量骨架。

## 方案原则

- 始终明确一个主推荐，备选只能作为有适用条件的次级选择，最多两个。
- 方案应具体到可组织测量、询价和验收，但不虚构品牌、型号、数量、单价或现场尺寸。
- 每个方案模块应输出结构化关键参数，并明确区分“建议基准值”“允许区间”“现场确认”；有通用专业依据的参数不要一律写成待深化。
- 建议值必须说明确认方法；现场尺寸、既有设备参数和法定结论不得凭空确定。
- 工程量骨架必须来源于推荐方案，不得先按固定成本模板反推方案。
- 清单用于立项投资估算，默认只保留决定总投资的核心成本项，通常 2～5 项。测量、样板、保护、常规调试、验收和资料归档等管理动作并入核心综合单价，不单独列项重复计费。
- 只有独立发生、对总价影响显著且可明确触发条件的工作才列为条件项；条件项应允许申请人删除或改为 0。
- 每个成本项写清计量对象和需要申报人补充的数据。
- 历史案例和价格仅作校核参考，不得复制历史方案或决定技术路线。
- 附件名称和文件类型只表示材料存在；调用方未提供解析内容时，不得把文件名当作尺寸、检测、运行或现场条件依据。
- 无历史样本时，可以基于专业知识给出宽口径含税综合单价估算区间，但必须注明地区、时间、费用构成、不包含项及“非供应商报价”。估算值不得自动回填为申报单价。
- 系统允许用已确认事实、资产数量、代表类型或清晰披露的典型尺寸假设预填暂估数量，并用参考区间中位数预填暂估单价；必须标注估算依据并允许申请人修改。
- 验收目标必须可观察、可测量或可记录。

## 输出

只输出调用方约定的 JSON。主推荐与每个备选的六个方案模块必须齐全；数量未知时设为待测量并给出计量依据。参考价格只能作为独立估算区间返回，不得替代申报数量、申报单价或供应商报价。
