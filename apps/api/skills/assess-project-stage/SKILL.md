# 工程阶段判断

以当前项目事实和证据为主，给出必要性或可行性阶段的专业判断。需要类别判断时读取 [references/category-judgement.md](references/category-judgement.md)。

## 最少输入理解

必要性阶段获得问题描述和位置后，先复述对问题、位置和影响的理解，列出已确认事实和最关键缺口，并在需要时只提出一项有明确用途的材料请求。让填报人确认或纠正理解，再继续判断，不要把信息不足包装成结论。

## 判断顺序

1. 核对当前阶段的已确认事实、证据摘要和已触发风险。
2. 区分事实缺失、证据不足、专业风险和可接受假设。
3. 使用工程知识判断必要性、维修替代性、技术闭环和风险可控性。
4. 仅从输入的已发布题目 ID 中选择追问，不创造题目。
5. 每次只选择最影响当前结论的一项追问；材料请求须说明用途，并允许照片、工单、巡检、检测等同等证据替代。
6. 输出一个明确倾向；不要使用评分或概率。

## 动机与门槛

- 品质与形象提升：观感老旧、空间品质、企业形象或统一标准可以构成原则必要性。允许代表性照片、抽样现状或管理台账，不要求逐台故障、逐台投诉、逐台维修史。
- 生命周期更新：以使用年限、维护状态和更新策略判断，不要求先证明已发生严重故障。
- 故障整治：才要求问题、后果、维修替代性和按状态纳入形成闭环。
- 合规、节能和扩容分别按对应目标判断，不得套用故障整治口径。
- 必要性只审 `principle` 与 `scope_strategy`。`implementation_readiness` 缺口输出为实施条件，不能生成必要性补充表。

## 范围校准

- 始终区分原申报范围、现有事实支持范围和当前确认范围。
- 当补充材料只证明原范围中的一部分，但该部分本身可独立立项或实施时，不得继续把“证明全部原范围”作为唯一补充要求。
- 此时必须输出范围校准建议：明确已支持部分、未支持部分和差异依据，交由填报人选择缩小范围、维持原范围继续补充或纠正识别。
- 范围校准不是批准，也不消耗补充轮次；确认后按新范围重新判断必要性、方案和工程量。
- 只有范围不可拆分、局部实施会造成系统性风险时，才可以拒绝缩小范围，并须说明专业原因。

## 依据优先级

按以下优先级使用信息：

1. 当前项目已确认事实与证据。
2. 工程专业知识及已发布知识包。
3. 当前项目明确写入的合理假设。
4. 历史案例，仅作为低优先级旁证，不得作为唯一依据或直接否决条件。

没有历史案例时仍须独立完成判断。历史案例与当前事实冲突时，以当前事实和专业知识为准。

## 边界

- 不替代完整性硬门槛；必答、证据关联和预算闭合由系统检查。
- 不伪造法规、检测结论、现场状态或附件内容。
- 不能因为缺少招标后深化资料而否定立项可行性。
- 风险有明确控制措施时判断其是否可控；只有关键事实无法判断时要求补充。
- 必要性不足时应明确倾向不批准，不要用中性措辞回避。

## 输出

只输出调用方约定的 JSON。理由最多三条，每条必须能对应输入事实、证据或专业判断。缺失事实应写成可执行的补充要求。
